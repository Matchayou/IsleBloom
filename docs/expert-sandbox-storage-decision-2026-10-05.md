# 专家独立沙箱与独立存储：架构决策

日期：2026-10-05。用户已选择：**每个专家独立沙箱，并拥有独立存储。** 本文将该要求纳入此前上下文工程选型；状态是已明确目标和实施契约，尚未实现或完成沙箱验收。本轮维持调研范围，不修改生产代码、不启动容器、不操作历史服务和数据。

**编码专家需求更新：** [统一完整选型](multi-agent-context-architecture-2026-10-05.md)增加“专属 worktree + 受控 Git 工具”，与沙箱、私有卷同时使用。允许挂载当前任务专用代码目录，不挂载用户主 checkout、其他专家目录或共享 Git 管理目录。新的总体实施顺序以统一文档为准。

**ShareAI / Claude Code 调研补充：** [补充文档](shareai-claude-code-context-supplement-2026-10-05.md)确认课程的独立消息、线程和 worktree 不能替代此处的 OS 边界；正式交接采用中央持久事件，压缩产物、完整 transcript 与检索索引同样纳入私有存储和撤权管理。本篇隔离决定与实施顺序不变。

## 1. 决策

采用 Docker 容器隔离专家的本地执行进程，每个专家会话拥有独占的数据卷，保存自己的 SQLite 工作数据库、草稿、阅读索引与检查点。原有 PostgreSQL 和 DBOS 留在可信协调服务，负责任务、授权、固定报告、证据和最终提交。继续使用现有 OpenAI Agents SDK 运行模型循环，不更换 Agent 框架。

身份边界采用 `(research_id, expert_session_id)`，不采用全局的 `expert_id`：同一类专家在两个研究中拥有两个独立工作区。同一会话的后续任务可延续其获准记忆，但同一时刻只允许一个执行者写该工作区；各任务仍绑定自己的 task/spec/run 和授权版本。

主助手的模型执行也采用独立工作区和同样的沙箱边界。**可信协调服务与“主助手模型”是不同角色**：只有前者管理容器、密钥和权威数据库。主助手模型通过受控接口取得有权限的资料和正式交付，不能因为负责统筹就任意打开专家私有草稿库。

Docker 提供隔离的文件系统、网络与进程树；持久卷与容器生命周期分开。这里承诺操作系统容器边界及独占存储，不承诺每个专家独占物理机、内核或虚拟机。Mac 上 Docker Desktop 的 Linux 容器运行在 Linux VM 内，也不等于每个容器各有一台 VM。[运行容器](https://docs.docker.com/engine/containers/run/)、[持久卷](https://docs.docker.com/engine/storage/volumes/)、[Mac 权限和 VM 边界](https://docs.docker.com/desktop/setup/install/mac-permission-requirements/)。

## 2. 这比当前系统多了什么

当前 `composition.py:154` 明确由专家复用主服务的 database、scopes 和 research；各专家通过同一进程中的 Python handler 访问业务服务。现有 scope 能阻止越权工具请求，但不是操作系统边界。

新的要求意味着模型循环与专家工作存储必须从共享服务中拆出。只给数据库记录增加 expert_id、给文件换一个目录、或复制一份共享数据库连接，都不能算完成。

当前 PostgreSQL 适配器还有“同一主机同一 OS 用户只允许一个执行进程”的全局锁（`adapters/postgres/__init__.py:23–47`）。本方案保留协调服务作为中央库的唯一业务执行者；沙箱 worker 不实例化这个数据库适配器。不能通过取消现有锁来冒充支持多个隔离执行者，也不能把整个旧应用复制进多个容器并让它们争用中央库。

2026-10-05 的只读环境检查：发现 Docker CLI；`docker version` 无法连接其当前配置的本地 socket，错误为 socket 不存在。**当前无法确认 Docker daemon 可用，尚未运行容器隔离测试。** 没有启动 Docker、切换 context、拉取镜像或改变主机设置。

## 3. 数据放在哪里

| 位置 | 保存内容 | 哪些角色可访问 |
| --- | --- | --- |
| 中央权威仓储 | 原始资料固定版本、任务单、授权与撤权、正式交付、证据、取消状态、预算与交接记录 | 可信协调服务；模型只能通过授权接口访问选定内容 |
| 主助手独占卷 | 主线工作摘要、计划、阅读进度、局部缓存 | 当前研究的主助手沙箱 |
| 专家 A 独占卷 | A 的草稿、已获准的资料片段、SQLite 工作库、阅读索引 | 该研究的 A 会话沙箱 |
| 专家 B 独占卷 | B 的草稿、已获准的资料片段、SQLite 工作库、阅读索引 | 该研究的 B 会话沙箱 |

采用 SQLite 的原因是它适合每个工作区单写者的本地状态，本地运行库已可由 Python 提供；不需要为每个专家部署一套 PostgreSQL 服务。它不是重新实现中央业务仓储：中央结果与权限仍只有原 PostgreSQL 一份权威状态，SQLite 仅拥有专家的私有工作数据。

SQLite 文件本身不提供进程隔离；有效边界来自容器只挂载自己的卷、没有其他存储路径或凭据。单独 PostgreSQL database 也需要正确的连接和权限配置，单独 schema 更不能替代沙箱，因此本轮不采用“共享进程中分几个库/表”的实现。[PostgreSQL 数据库隔离说明](https://www.postgresql.org/docs/current/manage-ag-overview.html)、[schema 边界](https://www.postgresql.org/docs/current/ddl-schemas.html)。

专家工作库只需存当前业务必需对象：带出处的笔记、已读片段记录、上下文摘要、运行检查点。笔记状态与已核验事实分开。正式报告先作为待提交产物上交，由中央服务重新核对任务版本、权限、取消、schema 和引文，成功后才进入原报告仓储。专家不能在自己的库中把 delivery 或 adoption 改成 passed/adopted。

## 4. 沙箱最小配置与通信

容器使用固定镜像摘要、非 root 用户、只读根文件系统、独占工作卷、有限的临时目录，并限制 CPU、内存和进程数；丢弃不需要的 capabilities，启用 no-new-privileges，保留 seccomp 限制。不使用 privileged、host PID/network，不挂载宿主主目录、项目根、共享 blob 根目录、中央数据库文件或 Docker socket。工作区磁盘用量也需要受控；不能把文件工具的检查误称为底层卷已具备硬配额，实际卷容量限制须在实现时验证。[Docker 权限模型](https://docs.docker.com/engine/security/)、[seccomp](https://docs.docker.com/engine/security/seccomp/)。

初版容器使用 `network=none`。所有外部模型请求、网页搜索/抓取、跨专家消息和资料授权，通过由协调服务持有的容器标准输入/输出通道传递。只传固定 schema 的业务消息，协议通道与普通日志分离；有消息大小、序号、操作 ID 和速率限制。容器没有服务商密钥，也不能自由指定宿主文件路径、数据库地址或任意 HTTP 目的地。

协调服务将每条通道绑定到它创建的 container/session/run/attempt，不能相信请求正文自报的 expert_id 或 scope。每次操作重验任务身份、授权版本、取消与剩余额度。模型请求只能使用该运行已固定的模型和输出契约，不能通过请求参数要求代理提高权限、换模型或转发到任意地址。

模型循环仍在各沙箱中，由 Agents SDK 执行；通过 SDK 的 `Model` 扩展点将调用传给协调服务，后者继续使用现有提供方适配与凭据。已检查本地 0.22.2 的 `Model.get_response`、`ModelResponse` 接口；模型/工具调用 ID 与使用量需完整往返。此适配必须做真实 SDK 的受控模型协议测试，不重新手写提供方 HTTP 协议，也不因为隔离而切换模型。[SDK Model 接口](https://github.com/openai/openai-agents-python/blob/v0.22.2/src/agents/models/interface.py)。

此处隔离的是本地代理执行、工具、文件和状态；远端模型推理仍在当前模型服务商运行，不能把本地 Docker 描述成远端模型的物理隔离。

## 5. 跨专家协作怎样继续

1. 中央服务固定任务版本与 ContextPacket，只发送该任务获准的输入或资料引用。
2. 专家在自己的工作区整理上下文、读写笔记、查询本地已授权片段；需要新资料时向协调服务申请。
3. A 需要 B 的报告时，走原主助手信息交接流程；B 的正式交付已经进入中央仓储，主助手实际读取后授权固定版本，A 得到授权副本或引用。
4. A 不能访问 B 的数据库或卷；B 的私有草稿不会因为“同一主任务”被自动导入。
5. 专家提交结果后，中央服务检查并发布，主助手收到交付通知再进行汇总。待复核报告仍只是讨论材料，不能变成正式采用。

原有授权请求、取消、固定版本和证据检查继续位于服务端，不由容器自报结果取代。容器隔离与 context 选择是相互独立的要求：即使每人有自己的数据库，也仍需控制哪些片段进入活跃窗口；独立存储不会自动压缩历史或修复语义判断。

## 6. 必须解决的三个生命周期问题

### 撤权后已经缓存的资料

只撤销下一次读取权限不够：专家可能已把原文抄进笔记、摘要或 SQLite。不能只删除原文件就声称专家已经忘记。

首版采用保守且可验证的规则：工作区记录全部曾接收的来源/报告依赖。任一依赖撤权、任务权限收窄或节点排除时，协调服务立即作废通道、停止相关容器、使旧工作卷退出可执行状态。未来运行使用新授权世代的干净卷；不自动复制旧摘要或模型生成笔记，只导入重新校验通过的输入。旧卷若为审计保留，放在任何专家都不能挂载的隔离存储中；历史正式报告留在中央仓储，并按原权限限制读取。

这个过程是权限撤销时创建新的执行上下文，不是历史数据库迁移，也不修改旧报告。已发给模型服务商的请求或已经交给用户的内容无法通过关闭容器追回，不能作此承诺。撤权后迟到的模型/工具返回和最终产物必须被拒绝，不恢复发布资格。

### 崩溃与恢复

容器按运行创建，工作卷按会话持久保留。正常崩溃且授权未变时，可将同一会话卷挂到替代容器；同时只能有一个写者。恢复必须重验 task/spec/run、scope 世代、镜像/方法/模型和剩余额度。

中央 DBOS 保持调度权威；专家工作库不是另一套调度器。明确区分工作区检查点与中央正式提交：专家将待交付产物和稳定操作 ID 保存后提交，中央事务只接收一次，确认回执可重放。中央已经提交但容器未收到确认时，查询同一操作即可，不再次生成报告。

模型请求已发送而响应尚未持久化的窗口仍可能产生重试；记录未知用量与尝试，不保证外部 API exactly-once。不允许容器通过重启清零预算。故障恢复保持固定契约；不兼容状态明确拒绝，不加旧协议转换层。

### 取消与资源回收

取消先在中央持久化并封锁新操作，再停止容器及其子进程。无论停止是否立即完成，旧运行都丧失发布资格。释放运行资源不等于删除专家工作数据；保留/归档工作卷与删除研究资料是不同操作。磁盘满、内存超限、通道失联都要得到可查询的终态，不能通过自动无上限重建容器掩盖失败。

## 7. 最小可运行实施顺序

| 阶段 | 完整可验证的能力 | 主要改动 |
| --- | --- | --- |
| 1 | 一个受控专家在真实容器内接任务、写私有笔记、恢复读取并提交可验证结果 | 窄的容器执行适配、固定消息通道、工作区 SQLite；保留现有 SDK 与中央提交路径 |
| 2 | 两专家并发，不能读取彼此文件/数据库/进程，也不能访问宿主或网络；各自持久恢复 | 沙箱配置、独占卷、会话单写者、负向隔离测试 |
| 3 | 原授权交接、信息等待、取消、撤权和固定版本在沙箱路径端到端工作 | `collaboration/information.py`、`history.py`、`tasks/service.py`、执行入口；中央身份验证不能下放 |
| 4 | 主助手采用相同执行边界；其正常对话、专家咨询以及专家讨论均走同一隔离契约 | `app/research_execution.py`、`projects/service.py`、SDK 模型传输适配 |
| 5 | 每个工作区接入阅读账本、分页、摘要与收尾预算，检验真实任务质量 | 原上下文选型中的 context/execution 模块，中央保留权威预算与证据校验 |

新执行契约通过隔离验收后替换产品的共享进程执行路径，不保留一个用户可选的“隔离失败就直接在宿主执行”分支。开发时使用全新隔离的实例、库和卷验证，不改 8771/8782/8783 或其历史数据；已有历史报告只读保留，不进行迁移。具体上线安排与生产替换不属于本次研究操作。

## 8. 验收门槛

必须用真实容器执行负向用例，不能只 Mock Docker 命令：

- A 的文件/SQLite 存独有标记，B 即使知道数据库名、绝对路径和会话 ID，也读不到；相同 expert_id 在另一研究中同样读不到。
- 沙箱不能列出宿主进程、访问宿主项目/密钥文件、打开 Docker socket、直接连接中央数据库或另一专家；直接互联网请求失败，获准的 broker 搜索仍能工作。
- A 的笔记在正常容器替换后存在，B 的卷从未被挂载；同一会话竞争启动时只有一个合法写者。
- 伪造 session/run/报告 ID、中央权限、模型地址或已通过复核状态均不能扩大权限。
- 正常报告授权交接能成功，A 得到准确固定版本；未授权正文与 B 的私有草稿不可见。
- 撤权发生在已缓存、已摘要、在途请求、检查点恢复或发布前，均禁止继续使用旧工作区；没有手工删除笔记的前提也能成立。
- 取消后子进程停止、迟到提交被拒；容器崩溃/重试不重复派发、不覆盖初报、不重置预算。
- 单个专家耗尽内存/进程/磁盘资源时有明确终态，其他专家仍可交付；实际磁盘限额未配置时不得标该项通过。
- 收尾、引用、固定版本、语义复核与原信息交接回归通过。容器能启动不代表上下文选取质量合格。

目前上述沙箱验收均未执行。当前 Docker endpoint 不可用，实施验证需要可用运行时；在运行时就绪前可以完成协议与业务单测，但不能宣称已经实现操作系统隔离。
