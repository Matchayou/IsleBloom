# 最终报告纠错与后台汇总

## 实现

1. 使用现有 OpenAI Agents SDK 的 `AgentOutputSchema.validate_json`、`RunResult.to_input_list()` 和 `Agent.clone()`。校验失败的草稿留在原对话中，向同一专家反馈字段级错误，最多追加两次格式纠正；仍受原运行的总轮次与超时限制。
2. 纠正回合移除工具，只整理已有证据与报告。所有请求计入用量；原始错误草稿和校验问题保存在运行结果的 `output_repairs`，不作为正式报告发布。成功后仍走既有报告、引用与回执校验；失败则保留失败状态及诊断。
3. `delegate_task` 统一接受后台任务并立即返回。删除同步等待及 `wait_for_result` 参数。主助手同轮派发全部专家后返回处理中，后台任务按原有并发控制执行。
4. 以现有 `manager_run_id` 归组，同轮所有任务成功或失败后才汇总。纠错包含在专家运行内，所以不会在 B 尚在修正时提前汇总。
5. 汇总续接开放 `read_context`、`read_source`、`search_source`、`get_task_status`，可读取双方完整报告和获准的已保存原始正文。续接不包含派发或联网工具；无需重启调查。
6. 初始输入只放结果目录与短预览。超大的批量读取返回可恢复提示；已获准的大资料可用定位检索读取。只有实际返回正文的资料才登记为已读，仍保留原有长度与权限限制。
7. 汇总区分新证据、结论变化、已解决分歧、剩余未知及交付复核状态。一侧最终失败时给出有依据的部分结论并说明失败影响。待复核报告可以用于讨论，正式采用仍须独立复核。
8. 通知只确认已纳入本轮固定输入的结果。即使专家在主助手写完“处理中”前已完成，也不会误标为已汇总。

## 测试

完整回归：`PYTHONPATH=src .venv/bin/pytest -q`，**285 passed / 176 skipped**。需要监听本地端口的资源测试在获准的环境中执行；跳过项不视为通过。

- `tests/test_sdk_contract.py`：真实 SDK 配合受控模型，覆盖 JSON 截断、代码围栏、缺字段、错误类型；核对完整对话、工具不重跑、用量累加、轮次和两次纠正上限。
- `tests/test_report_delivery.py`：A 先完成、B 延迟并经 SDK 修正后交付，随后恰好一次汇总；以及 B 修正耗尽、A 结果保留的路径。
- `tests/test_collaboration.py`：快速完成时的通知确认、重复恢复不重复汇总、新用户消息、失败续接、并发执行。
- `tests/test_disagreement_followup.py`：两位原专家分别补查，主助手在后台完成后读取新报告及原始正文，再给出综合结果；包含一侧搜索无结果。

真实模型复验见 [自主补查审阅记录](collaboration-c4-autonomous-research-review.md)。受控格式错误测试与真实模型自主行为分别记录，不能混为同一证据。

真实复验：A 的最终 JSON 真实出错并纠正一次，B 直接成功。两侧报告保留，修复上下文超限后仅重试主助手汇总并成功。中途有操作员重试，内容仍有语义缺陷，详见审阅记录；不宣称 C4 全部通过。
