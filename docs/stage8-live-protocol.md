# Stage 8 真实模型验收协议

冻结于 2026-10-03，首轮调用前制定。使用 DeepSeek Flash 的 OpenAI Chat Completions 接口、独立 Stage 8 数据库及固定年报摘录。

比较模板 v2 与等价手工 ResearchPlan：相同目标、方法、输入资料与依赖，各运行 3 个公司节点及 1 个比较节点。不用文本逐字一致作为标准。

通过要求：

1. 两条路径的 8 个步骤均完成业务提交，结果与输入版本可查询。
2. 各公司仅挂载自己的资料；最终比较准确挂载本次 3 个上游结果。
3. 核对 2025 年合并经营现金流：Tesla 14,747 million dollars；Ford 21,282 million dollars（不得取不含 Ford Credit 的 8,351）；GM 26,867 million dollars。
4. 金额换算必须一致，不得把 million 当 billion；若比较规模，排序为 GM > Ford > Tesla。现金流规模不能直接推出经营质量或风险的排序。
5. Tesla 资本开支 8.53 billion dollars 仅在引用该摘录时可用；Ford/GM 摘录没有资本开支，须保留缺失，不能假设为零或编造自由现金流。
6. 各公司竞争/经营风险与摘录内容一致；重要来源事实提供位置，缺失、假设与跨公司口径限制保留。
7. 用量与失败如实记录。脚本/模型自检不能替代独立核对；本轮只验证版本化复用与业务一致性，不宣称方法质量提升、RouteLLM 双模型收益或节约费用。

若失败，保留原结果与配置，修复实际 gap 后创建新实例复验；不覆盖历史结果，也不降低上述要求。

## 传输配置修正

前两次尝试发现 Chat Completions 不接受 SDK 的 JSON Schema response_format（HTTP 400）。凭据和模型可用性检查通过。后续明确使用现有产品与 SDK 默认的 Responses API；官方接口支持 `text.format.type=json_schema`：https://api-docs.deepseek.com/api/create-response/ 。只修正验收脚本的接口选择，不修改质量要求、输入、任务拆分或校验规则，不添加自动协议 fallback。原始失败记录保留为 `stage8-live-attempt-1.json`、`stage8-live-attempt-2.json`。

## 引用方法修正

第三次尝试保留为 `stage8-live-attempt-3.json`：模型产生结构化输出，但引用字段改写成原文没有的词语，严格证据校验拒绝发布。人工编写 synthesize-evidence-v2 / analyze-evidence-v2，模板 v3 固定这两个版本；仅增加通用的原文字段定位规则，无公司名、数值或验收答案。模板与手工对照均使用相同新版方法，原输入和七项要求不变；未修改证据检查器或加入自动候选/自动晋级。

## 原文复用修正

第四次尝试中，模板三个公司节点通过严格证据校验，但比较节点重复读取输入已经完整包含的 `content[].fragments`，用尽 8 次工具调用预算。方法 v3 明确已有原文直接引用、缺原文时才读取，并聚焦目标期间；模板 v4 固定方法 v3。该轮手工路径还出现一次超时与一次公司字段改写（详细原始输出已保留）。保持原有预算、资料和七项要求，既不提高限额，也不关闭工具或降低校验。

## 单步预算传递修正

第五次尝试保留 `stage8-live-attempt-5.json`。计划总时限无法覆盖硬编码的单步默认 60 秒，导致有效请求超时。模板 v5 使用原有 RunLimits 显式设置每步 180 秒、计划 600 秒，编译到 PlanStep 并传入原 NodeCommand/Dispatcher；模板与手工对照使用同样预算，工具调用/轮数仍为 8，没有修改模型参数或降低内容标准。新增低时限回归证明预算传到实际执行器并仍会正确阻断超时。方法 v4 同时澄清公司元数据不能来自文件名，引用使用保持词间分隔的连续短片段，避免手工重建原文制表符。第五轮另有一次引用漏掉词间空白，未绕过严格校验。

## 独立引用完整性修正

第六次尝试八步均发布，但 Codex 独立核对发现最终比较的部分竞争风险引用只覆盖跨行句子的前半句。保存为 `stage8-live-attempt-6.json`，不把程序成功当完整语义通过。方法 v5 增加完整引用、明确比较限制的规则，模板 v6 固定方法 v5；预算及其余条件与第六轮相同，再次对照模板与手工执行。

## 引用边界示例

第七次尝试保存为 `stage8-live-attempt-7.json`。一个引用把相邻片段的词拼入单个 quote，被原校验拒绝。方法 v6 增加纯字母合成示例，演示跨片段应分别引用、每个 quote 必须是一个 fragment.text 的连续子串；模板 v7 固定方法 v6。资料、模型、预算和内容要求不变。

## 精简方法与正文

第八次尝试中模板四步均发布，但手工路径一次返回无效 JSON，SDK 正确拒绝（`stage8-live-attempt-8.json`）。方法 v7 去重规则，约束正文聚焦目标年份、合并同一事实的说明，保留必要引用与缺失；引用边界示例保留。模板 v8 绑定方法 v7。内容标准、预算、资料和模型配置不变，不修改 JSON 解析器或接受残缺输出。

## 摘录空白规范化

第九轮模板四步均发布，但手工 Tesla 引用再次把制表符分隔的 `of established` 粘连，原校验拒绝。记录为 `stage8-live-attempt-9.json`。第十轮仅将验收摘录每行空白规范化为单空格，使用既有 EvidenceService 的同一 canonicalization，逐文件断言词序、文字与行数均不变。保留原始摘录及 hash、新摘录及 hash 于 `stage8-live-input-manifest.json`，新文件在 `stage8-packets/`。两条路径挂载同一批新版本，方法/模板/模型/预算/七项标准不变。此为验收文本整理，不修改生产解析器或证据检查规则，不能据此宣称模型已解决任意原始格式的引用问题。

## 显式恢复验收（前序 Stage 6 集成）

第十轮模板四步通过，但手工 GM 节点发生 SDK 输出契约错误；该次原始提供方正文未捕获，不能断言是截断还是结构错误。固定输入重试使用原方法、资料及预算，成功返回完整有效 JSON（`stage8-provider-diagnostic.json`），并未复现旧错误。随后使用原有 adopt 命令重算下游比较；首次重算引用匹配失败，再以固定输入 retry 成功，精确挂载三个成功结果。首次八次运行及额外的重试、比较重算及比较重试三次运行全部保留，不计作一次全成功。最终仅核验恢复后的八个节点是否达到原内容标准；这不是稳定性、质量提升或费用优势证明。恢复脚本为 `verify_stage8_response.py` 与 `verify_stage8_live_recovery.py`、`verify_stage8_comparison_retry.py`，针对保留的第十轮记录，不是新增生产运行器或自动重试机制。
