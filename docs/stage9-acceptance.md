# Stage 9：可选偏好与获准记忆验收

日期：2026-10-03。范围以《当前产品-增量开发与技术选型》第 12 节和《产品设计-当前版本》第 8、9 节为准。Stage 10 未实施。

## 实现与复用

用户可在工作区保存个人或当前研究范围的偏好、获准经验，并查看来源、确认状态和版本；可修改、暂停、删除。专家任务创建时明确勾选条目。任务单固定记忆 ID 与版本，`ContextBuilder` 将获准内容、来源和适用范围装配进本次输入。执行前、跨进程恢复前和提交前重验当前状态与版本。当前任务指令优先；记忆不是事实引用，不能掩盖反证。未勾选或删除后，新任务仍沿原执行链路工作。

参考项目 BearCode 的 `agents/memory.py` 使用项目隔离、轻量索引、相关条目选择和历史信息新鲜度提示；其 `agents/skills.py` 将方法与记忆分开。本阶段采用这两个已证实的边界，直接复用本仓库的 `TaskSpec`、`ContextBuilder`、`ScopeService`、`PostgresDatabase`、SQLAlchemy、Pydantic 和 React。当前链路无需另建文件索引、向量库、side query、Mem0/Letta 或自动写入。专家方法仍属于 Stage 8 版本资产，任务事实仍属于资料与结果版本。

## 设计核对

| 设计要求 | 实现与证据 |
|---|---|
| 保存“公司研究先看现金流”，新任务显式应用 | 管理面板确认保存；任务创建请求带 `memory_ids`，`TaskSpec.memory_refs` 固定版本；`tests/test_memories.py` 和 `stage9-browser.json` 验证实际任务输入 |
| 本次指令覆盖旧偏好 | 任务 `goal` 保留原指令；上下文与专家系统指令要求当前任务优先；浏览器控制引擎及 DeepSeek 真实模型控制案例均验证风险先于现金流 |
| 删除后不再召回 | 条目物理删除；后续选择拒绝，未勾选任务无 `approved_memory`；浏览器删除、后续运行和刷新验证 |
| 来源、确认与过期 | 每条记录必须有来源；`draft` 不可选，确认后方可用；带时区到期时间过期后不可选；API 与阶段测试覆盖 |
| 范围隔离 | owner 与可选 research_id 双层检查；研究专属条目不进入其他研究的列表或任务；切换研究时清空全局条目的勾选状态，须再次明确选择；阶段及浏览器测试覆盖 |
| 撤权和修改 | 条件版本更新；修改、暂停或删除使旧任务版本失效；在途删除后提交为失败回执；阶段测试覆盖 |
| 事实与方法分离 | 记忆只含偏好/获准经验两类；不能成为 `ResourceRef` 或引用来源；原证据检查和专家方法版本不受改写 |
| 停用后基础研究 | 不选记忆的旧任务路径和删除后的新任务仍执行；Stage 0–8 全量回归覆盖 |
| RouteLLM 与预算连接 | 路由预览计入选中记忆的输入长度；记忆正文不传入 Jev 的获准摘要；超模型容量时阻断，阶段测试覆盖 |

## 限制

本阶段不自动从反馈或历史对话提取记忆；保存和确认均由用户明确操作。来源由用户输入，不能单靠该字段证明经验真实或普适。当前显式选择不需要语义检索；记忆不会替代来源证据。真实模型控制案例通过，但首次尝试有一次 SDK JSON 协议失败、用量未知；单一虚构资料不能证明普适语义稳定性。Stage 5/R1 真人语义签收及 Stage 7 双模型 RouteLLM 收益验证仍是独立待办。
