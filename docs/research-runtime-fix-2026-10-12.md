日期：2026-10-12。继续使用已安装 OpenAI Agents SDK、ResearchPlan、Dispatcher 和受控执行账本，没有增加框架或依赖。

## 改动

1. 研究回答和计划生成采用 SDK 严格 JSON schema。DeepSeek 已文档化的两个 Responses 模型使用明确调用策略：调查 `reasoning.effort=low`，摘要与无工具交付 `none`；其他模型保留原 SDK 参数。依据 [DeepSeek Responses 文档](https://api-docs.deepseek.com/api/create-response/) 的参数能力，不把DSML文本解析成工具执行。
2. 非JSON答案中的DSML工具标签标为 `model_protocol`。原有SDK格式修正链在原预算内纠正，工具继续关闭；不能纠正时保存明确失败。SDK会保留无效草稿和诊断，不把它作为正式研究结果。
3. 移除12000字符摘要触发。确定性投影估算的输入加输出预留和安全余量达到窗口80%，或投影无法容纳/提供商明确拒绝窗口时，才尝试压缩。沿用完整轮次、来源校验、增量摘要与持久化游标；最终交付阶段不启动摘要。当前仍使用项目保守65536窗口，未宣称扩大到供应商最大窗口。
4. 收尾至少获得单步时限的一半，结合已完成任务模型的最大耗时×预留轮次，最高占单步时限75%。摘要耗时不作为任务模型时延基线；时间观测保存到manifest，检查点恢复后可用。600秒任务初始预留300秒。已有工具调用和摘要受剩余调查预算限制，不能扩展批准的总deadline。
5. 批准后的模型当前命令只包含已编译步骤。原规划request/history仍保存在提案，当前handoff保留批准身份、版本、步骤及历史记录引用。原节点研究约束仍在handoff中；不再把“当前只生成计划”重新加入执行目标。SDK历史与工具结果继续保留，不重置模型调查过程。
6. 响应头阶段记录HTTP状态和请求ID；返回响应时记录ID；流式response.created即记录ID，终态保留usage。取消/未返回usage仍是unknown，不能从关联ID推断精确费用。
7. DBOS代码版本更新为plan-v2，旧版本工作流不自动接管。SDK检查点恢复正确还原reasoning对象。旧执行记录和未知账单不修改、不重放。

参考了固定DeerFlow源码中按窗口压力压缩、提供商适配与阶段状态管理的模式，未照搬其框架、兼容分支或完整提示词。对应源码见 [根因报告](research-runtime-root-causes-2026-10-12.md) 的固定版本链接。
