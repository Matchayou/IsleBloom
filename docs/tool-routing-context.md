# 主助手工具路由与上下文边界

2026-10-09 实施。改造针对状态提问误入研究流程、空读取枚举整个资料库，以及新页面在下一次模型调用前又被外置的问题。

## 当前行为

- 主助手初始只暴露 `get_task_status`、`select_task_tools` 和 `read_context_page`。普通回答或已知状态解释可直接结束；需要实时状态时，只读相关任务。
- `select_task_tools` 选择资料、专家、管理或报告工具组。Agents SDK 的 `FunctionTool.is_enabled` 控制每轮实际工具定义，动态指令只附加所选组的流程。选择由当前模型结合完整语义完成，没有关键词路由器或额外分类模型。切换后旧组工具退出，选择保存在 SDK 检查点中。
- `GET /api/task_status?research_id=…&task_id=…` 直接返回指定任务的最新执行、派发、失败、版本和复核状态，不调用模型、不读取正文，也不扫描整个工作区的预算或其他任务。状态与授权检查共用同一服务实现。
- `search_context` 要求类别和查询，仅检索元数据；`list_context` 明确列举单一类别。默认每页 8 条、上限 20 条；结果及专家消息可按任务或会话限定范围，后续页使用 `next_offset`。全文逐项审计必须来自用户明确需求，提示词禁止自行遍历。
- `read_context` 只读明确引用，每类最多 5 个。空输入返回可纠正的 `invalid_input`，不再返回全库目录。`find_experts` 真正过滤查询、kind 和 required_tools，默认最多 5 个、上限 10 个；无匹配不再把全体专家塞回模型。查询为字面检索，不冒充语义路由。
- 主聊天初始来源只放最多 8 条元数据，正文按需读取。原授权及固定快照挂载仍完整保存。资料库增大不会让每轮模型输入随之线性增长。
- 投影在 60% 窗口占用时外置较早工具正文，保留最近 3 个工具结果，包括重复页面。确实超预算时返回更小的真实文本片段和前进游标，不能只返回同一个工件编号。上下文页仍用 `read_context_page`，来源页仍用 `read_source`；来源定位、hash、版本和授权检查保持有效。
- 继续使用 `delegate_task` 的后台专家边界。交接具体问题、选定输入与交付要求；回传结论、引用、版本、复核状态和缺口。专家私有笔记和完整调查过程不自动进入主助手输入。

## 设计依据与保留边界

采用已安装 OpenAI Agents SDK 0.22.2 的动态工具启用、动态 instructions 与公开 RunState 导出/恢复接口，沿用现有受控 broker 和账本；未新增代理框架、依赖或旧接口兼容层。工具组选择只是模型可见能力的收敛，实际权限仍由固定 admission、scope 和工具校验决定。

输出仍使用现有 ResearchAnswer 结构，以保留证据保存与审核契约。2026-10-13 起任务输出上限为 16,384，摘要为 8,192，记忆选择为 2,048；任务推理与正文共同消耗输出预算。有效窗口与裁剪策略见 [预算调整记录](budget-and-travel-failure-2026-10-13.md)。初始输入使用 UTF-8 字节上界；续轮根据同一运行账本中的供应商实测输入用量校准，对未改变的完整消息复用测量，新增或修改内容仍按字节上界计入。工具、指令或 schema 改变时新头部全额计入，移除的旧内容不扣减。模型改变、缺少有效测量或没有相同消息时仍使用完整字节上界。审计分别记录实测基准、增量上界和最终估算，不能把估算冒充实测 token 数。新结果缩小后如仍无法容纳受保护约束，会明确终止为 context_budget，而非无尽重读。

验证使用真实安装的 SDK、隔离 PostgreSQL、确定性模型响应；这验证工具表面、数据流、存储及恢复契约，不等于外部模型的语义路由质量评测。另包含真实进程 SIGKILL 恢复测试。业务库不写入合成数据。

[实际初始请求表面](tool-routing-evidence/initial-surface.json)记录了一个隔离 SDK 测试运行：初始 3 个工具定义共 1487 字符、系统指令 751 字符，输出上限保持 8192；这是请求字符统计，不是外部模型实测 token 消耗。重点覆盖：

1. “你为什么没有派发资料搜集专家？”只读取指定失败任务；禁用目录、专家发现和正文读取仍能完成状态回答。HTTP 状态查询零模型调用，跨任务及撤销授权仍拒绝。
2. 工具按组加载、切换后旧组退出；空正文读取可纠正，选定正文在下一轮可见。
3. 资料从 9 份增至 102 份，模型输入始终 8 条元数据、零份正文，长度变化不足 10 字符。
4. 最新中文页面在预算压力下保留真实文本、准确原编号和前进游标；同批多个工具结果均不被隐藏。
5. 选择工具组后导出状态，重新创建执行器恢复；选择动作不重复，后续工具只执行一次。
6. 既有两专家派发与续接中，主助手可读公开报告，不能看到专家私有笔记；权限、来源校验、流式、幂等和进程中断恢复继续通过。
