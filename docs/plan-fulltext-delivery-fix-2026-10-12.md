# 全文获取与 Plan 交付修复

本次目标：验证 TinyFish 的 arXiv 全文通道，说明访问验证失败，区分阻断缺项与允许的研究局限，保留历史并验证三步执行。

## 已确认的抓取事实

OpenReview 请求 `https://openreview.net/pdf?id=WE_vluYUL-X` 被转到 `/challenge`；返回标题为 `Verifying your browser | OpenReview` 的验证页。直接请求同一 PDF 返回 HTTP 403 和 HTML。URL 一致性校验拒绝了替代页，不能将它当成论文。

TinyFish 成功获取 `https://arxiv.org/pdf/2210.03629`，转换后的 Markdown 有 110,816 字节，包含论文正文与参考文献。证据见 `plan-mode-evidence/arxiv-tinyfish-fulltext-probe.json`。正文获取成功不表示模型阅读了所有页或已核验所有结论。

## 实现

- TinyFish 检测访问验证页，返回 `access_verification_required`，保留 requested/final URL；普通地址变更返回 `source_url_changed`。验证页不入正文库，URL 安全校验保持。
- arXiv 的摘要与 HTML 发现结果同时提供独立 PDF discovery ref，优先显示全文候选。候选必须 fetch 后才能作为证据。
- `fetch_web(query=...)` 保存完整正文，同时复用 `search_source` 返回带位置的定向摘录，避免整份资料 JSON 的前 4,000 字符耗尽工具预算。检索结果按完整摘录裁剪至工具上限。
- `ResearchAnswer.blocking_missing` 仅表示未完成的必需交付；移除歧义的旧顶层 missing 字段，不提供别名或执行兼容层。`limitations` 保存允许的未知与证据边界。结果版本仍用 missing 表示阻断缺项，旧历史结果保持原判定。上游挂载和前端保留局限，真正缺项仍产生 partial 并阻止依赖执行。
- 主助手复用专家已有的 SDK 引用修正入口。逐字引文、位置和引用标识错误可在同一预算、关闭工具后受控修正。撤销访问和生命周期错误仍终止；最终保存仍再次核验引用。
- 研究结果用量以 ControlledLedger 的模型请求账本为准，执行失败不再自动等同于计费未知。恢复时对历史的保守未知标记读取账本审计，不改写旧 RunResult；真实未知仍拒绝恢复。
- 恢复提案冻结当前已授权研究库，复用之前抓取的正文；旧规划输入和旧运行不修改。Plan 步骤按需读取正文，避免全量内容反复进入模型。
- DBOS 代码版本为 plan-v5。继续使用原 SDK、ResearchPlan、确认机制和受控执行链。
