# 历史报告发现、读取与授权交接

2026-10-05：已实现并通过受控测试和一次真实模型验证。

## 工具变化

| 工具 | 调用者 | 当前行为 |
| --- | --- | --- |
| `read_information` | 专家回问时的主助手咨询回合 | 空参数列出当前主任务的资料和历史报告目录；`resource_refs` 读资料，`result_ids` 读具体报告正文、任务版本、运行及复核状态。只有本回合实际读过的报告可以授权。 |
| `read_context` | 正在执行正式任务的专家 | 空参数列出自己会话的历史消息、报告和明确获准的报告；`message_ids` / `result_ids` 读正文。自己的历史来源也须在当前授权范围内；他人报告须显式授权。 |
| `request_manager_information` | 正在执行正式任务的专家 | `requested_result_ids` 请求已知报告；不知道 ID 时通过 `question` 描述专家、阶段和所需内容。保存 `progress`，等待主助手答复，再继续原任务。 |

主助手正常回合已有完整 `read_context`，现在明确要求先查目录并尝试读取，再判断原报告是否可得。未挂载、访问受限、未找到与读取失败分别表达。

## 持久记录与权限

- `InformationAnswer.result_ids` 保存主助手选择的报告；服务端生成 `ReportGrant`，固定 `result_id`、`task_id`、`spec_version`、`run_id`，与原信息请求一起持久保存。
- 交付时再次检查主任务、来源权限、任务版本、取消状态和报告身份；恢复使用保存的授权记录。实际报告正文与来源依赖进入当前执行范围，原任务输入和历史报告不改写。
- 返回完整报告及交付/采用状态。待复核报告可以作为讨论材料读取，读取或授权不会把它变成已独立复核或正式采用的结果。
- 跨主任务读取、未读就授权、授权前撤权及篡改固定身份被拒绝；自己的会话也不能绕过来源授权。
- 无信息或部分信息时继续原任务，保留剩余缺口。仍沿用每次运行一轮信息请求；不新建任务版本或替换历史报告。
- 超过现有正文选取大小限制时返回可恢复提示，要求缩小选取；本次未新增报告分页。

同时修复信息请求产生内部 `expert` 消息后继续普通讨论的问题：送入模型时映射为 SDK 支持的 `assistant` 角色，持久记录仍保留专家身份。
