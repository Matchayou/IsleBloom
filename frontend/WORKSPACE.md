# 研究工作台

在现有本机服务打开 `/`。三栏工作台以真实后端研究为单位：左侧按研究主线分组，中央在研究总览、独立对话和独立专家任务之间切换，右侧查看资料、结果及获准原件。创建研究、上传资料、派发专家与创建分支从对应按钮打开。

## 操作

1. 点击“新建对话”输入研究目标。后端按研究复用唯一主线聊天；页面进入研究总览。
2. 点击右侧“上传资料”选择文件。请求传真实字节、文件名与 MIME，限制 25 MB；资料只授予当前研究。解析状态和问题显示在右侧。
3. 选择聊天节点进入独立对话后发送消息。页面先保存用户消息，再用返回的聊天 revision 发起回复。若消息已保存而回复未启动，可用原 command ID 重试回复；不会重新发送消息。202 表示后端接受，页面继续读取聊天与运行状态。消息或分支遇到 409 时应刷新后按当前版本再操作。
4. 在独立对话中点击“创建分支”，选截止消息并写分支目标。新分支固定继承截止点以前的消息快照，来源 revision 在聊天记录中保留。
5. 点击“派发专家”，选择任务种类、要求及必需资料或已通过交付复核的专家结果。创建任务单后派发；执行、交付复核和采用状态分别显示。任务创建或派发结果不明时先检查任务列表，避免重复执行产生费用。未运行任务可显式派发；后台运行任务可请求停止；保存失败的运行可用后端原运行 ID 重试保存。专家结果不会自动发布到聊天，也不会自动采用。
6. 右侧可查看结果版本与专家回执的正文、来源和固定输入；`resource_original` 会按所选研究当前授权检查后返回原件，不暴露本地路径。危险 MIME 以附件下载。

页面在切换研究时清空前一个研究的显示，请求响应按研究与对象隔离。研究、节点或任务、右侧选择保存在浏览器本地；刷新后仍要从后端重新读取并验证。密钥由后端进程环境提供，浏览器不保存模型密钥。

## 运行与验收

生产构建：`npm run build --prefix frontend`。将构建后的 `frontend/dist` 交给现有 `agent-research serve` 同源托管。开发代理使用 `frontend/vite.config.js` 的 `/api` 目标；写请求的 Origin 必须与浏览器页面同源。保留后端 Origin 检查。

独立无模型控制验收：启动 `.venv/bin/python scripts/verify_workspace_server.py`（127.0.0.1:8768，内存与临时 blob），然后执行 `node frontend/scripts/workspace-write-browser.mjs`。浏览器脚本创建有明确标记的合成研究与资料，验证完整链路、回复 202 后轮询、刷新恢复、409 和 403；该服务不保存进程重启后的数据，不检验真实模型质量或 PostgreSQL/DBOS 恢复。权限测试：`.venv/bin/python -m pytest tests/test_workspace_api.py -q`。正式数据库与后台执行仍按 README 中现有专用服务配置运行，测试不得指向历史验收库。
