# Stage 9 DeepSeek 真实模型控制案例核对

2026-10-03。使用 DeepSeek `deepseek-flash`、OpenAI Responses API、现有 SDK adapter 和 Stage 9 任务/记忆链路。密钥只经无回显终端送入测试进程；不在源码、日志或验收 JSON 中。输入为明确标记“虚构”的公司 A 单行控制资料：2025 年经营现金流 100 百万元、资本开支 20 百万元；竞争风险为新进入者可能压低价格。此验收不评价真实公司研究质量。

## 实际运行

第一次三任务尝试中，显式应用偏好成功；“本次指令覆盖”运行因 SDK 报 `Invalid JSON when parsing model output` 而失败；删除后的新任务成功。完整记录保留在 [第一次尝试](stage9-live-attempt1.json)。失败调用的用量没有完整回执，不能计为零。

第二次从相同控制资料和任务要求重新执行，三个任务均成功，实际输入与输出见 [完整记录](stage9-live.json)。此次没有把第一次失败冒充为成功，也没有以修改生产代码掩盖该协议错误。

| 链路步骤 | 实际检查 |
|---|---|
| 保存并在新任务显式应用 | `TaskSpec.memory_refs` 固定所选 ID/版本，运行输入含偏好、来源和范围；报告先给“经营现金流”，再给“竞争风险”，并明确说明该顺序取自获准偏好。 |
| 本次指令覆盖 | 同一条偏好仍在输入中；本次任务明确要求风险先。报告实际章节为“竞争风险”→“经营现金流”，并说明本次指令优先。 |
| 删除后不再召回 | 条目从可用列表消失；第三个新任务 `memory_refs` 为空，实际输入无 `approved_memory`；报告按当前指令风险先。 |

Codex 对照唯一控制资料逐项阅读第二次的三个报告：100、20 百万元及相减的 80 百万元均未冒充原文披露的自由现金流；新进入者可能压低价格被标为来源事实，其财务传导被标为推论；币种、口径、概率、幅度和期间对比等缺口保留；三个报告都说明资料是虚构控制样例。未看到记忆掩盖反证或被当作事实来源。任务回执为 `pending_review`，未伪装成人工语义签收。

第二次成功的三个任务共报告 6 次 SDK 请求、14,871 input tokens、6,784 output tokens。第一次尝试中两次成功运行另报告 4 次请求、10,510 input tokens、5,991 output tokens；失败运行用量不完整。因此这些数字只是已报告部分，不是两轮总消耗，也不能证明成功率、质量或成本收益。

控制案例验证了本阶段的实际模型行为，但不能推出任意偏好、任意资料或所有模型调用都稳定服从。Stage 5/R1 真人语义签收和 Stage 7 双模型 RouteLLM 收益验证仍须单独完成。
