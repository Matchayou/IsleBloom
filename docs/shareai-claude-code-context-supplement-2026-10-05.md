## 2. 用容易理解的方式说明当前问题

把模型的活跃上下文理解成桌面，把外部存储理解成资料柜，把沙箱理解成有门禁的办公室。目前已有资料柜和业务访问规则，但还没有给每位专家配齐自己的草稿本，也没有统一整理桌面；大家的执行代码仍在同一进程环境中。

| 用户关心的问题 | 现有项目的真实状态 | 本次补充后的目标 |
| --- | --- | --- |
| 每人是否有窗口外草稿纸 | 原始资料、报告、部分信息请求进度已持久化；通用笔记工具未接入当前主助手/正式专家工具集 | 每个主助手和专家有私有工作库，存笔记、阅读账本、摘要和检查点 |
| 能否正确、精简地取回资料 | 正式专家已有来源读取和报告授权；检索是指定资料内的词法匹配，部分目录固定截断，普通专家讨论没有检索工具 | 先看授权目录，再分页读固定版本片段；记录实际返回范围，用回归任务验证选取质量 |
| 是否能 compact | 未发现当前产品执行链的通用自动压缩；输入字符数硬限额不能算压缩 | 同时管理进入运行前的输入与运行中的工具历史，采用分层压缩 |
| 专家之间是否隔离 | 已有 scope、任务版本和信息交接；没有 OS 级执行隔离 | 消息、私有存储、工具能力、执行环境四个边界同时成立 |

本表沿用原选型的逐文件代码取证；本轮没有把规划写成已完成功能。保存到磁盘只能证明资料存在，不能证明检索正确；单独消息列表也不能证明其他专家读不到文件。

### 3.1 专家采用独立上下文，持续性由工作区保证

对于当前研究产品，合适的组合是“持续存在的专家身份与私有工作区 + 按任务构造的独立输入”。持续会话不意味着永久向模型重发全部历史，更不要求空闲容器常驻。沿用 `(research_id, expert_session_id)` 工作区身份；每次运行重验权限与版本。

主助手发给专家：任务目标、适用约束、验收要求、获准资料目录、必要的既有结论及出处、剩余预算。默认不复制整个主对话，不导入其他专家私有过程。专家返回：提交状态、关键结论及证据引用、未解决事项、正式报告 ID/版本。报告全文保存在中央权威仓储，主助手需要核对时再授权读取。短交付不能替代正式报告或独立核验。

课程 s06 是一次调用，s13 是持续队友，二者不是必须二选一的框架。官方文档也区分默认独立上下文与继承完整对话的 fork；本项目不默认采用完整历史 fork，因为它会扩大无关输入和授权面。[Claude Code 子 Agent](https://code.claude.com/docs/en/sub-agents)。

### 3.2 团队通信采用事件驱动，正式状态由协调器确认

借鉴 s13：专家交付、等待资料、失败、可接新任务分别记录；主助手由事件唤醒，不通过模型轮次反复查询“完成没有”。先盘点并复用现有 intent/notice/information 状态，不再造一套任务板。

课程 `MessageBus._read_unlocked` 读完即删除邮箱文件，保护它的是同进程的线程锁；适合解释通信，不足以承诺跨容器宕机恢复。我们的方案使用中央持久事件、稳定事件 ID 和消费确认，重复投递不重复提交。专家说“完成”只是候选结果，协调器检查通过后才正式交付。实现参考：[s13 code.py](https://github.com/shareAI-lab/learn-claude-code/blob/ce8f9f186058939da54c9d6fead78dfb5d0fd6c3/s13_agent_teams/code.py#L852)。

官方 Agent Teams 当前仍标为实验性，且列出进程内队友恢复、任务状态滞后等限制。因此不能直接把启动 Claude Code Teams 作为现有产品持久编排的替代品。[官方限制](https://code.claude.com/docs/en/agent-teams#limitations)。

## 4. 压缩路线：外部原文不变，活跃窗口分层整理

压缩应接在两个位置：**运行前**处理聊天、必需报告及工具定义；**每次模型请求前**处理新增工具结果和历史。只压缩 Runner 内的历史，无法解决当前 ContextBuilder 在调用模型之前就拒绝过长输入的问题。主助手正常对话、续接、专家正式任务、专家普通讨论都需覆盖同一契约，不能只改某一个入口。

以下是本项目的新增设计，不声称课程已提供这些业务保证：

1. **先可靠保存，再移出窗口。** 将完整工具结果与原始事件写入该工作区，保存版本、哈希、来源依赖、操作 ID。只有持久化成功后才以短预览和受控引用替换正文。回查读取保存的结果，不重新执行可能有副作用的命令，也不重新搜索后冒充旧证据。
2. **先做确定性的缩减。** 对已送入成功模型请求的旧工具结果保留“问题—有效发现—来源与范围—回查引用”。最近结果保留；过大的新结果也先落盘并给预览。完整原文存在不等于模型读过；预览、完整返回、引用、独立核验分别计量。低于预算时不无条件清空旧结果。
3. **再做有出处的滚动摘要。** 根据上个摘要及尚未覆盖的完整回合生成新摘要，记录覆盖游标和依赖；保留近期完整回合。当前用户要求、仍有效的明确约束、取消、权限、任务和预算状态从各自权威记录注入，不能靠摘要猜测或授予权限。摘要是可复核参考，不是证据原文。
4. **仅对明确的窗口超限做有界补救。** 提供方返回可识别的上下文超限时，重新投影并最多补救一次；若没有实质缩减或仍超限，结束为可恢复失败。撤权、取消、schema 错误不能归为超长而重试。摘要失败不以“已整理”空占位删除旧历史。

建议摘要保留：目标与有效约束引用、已完成与待办、已证实结论、待验证假设、已纠正的旧说法、证据定位、未解问题、下一步；摘要外附生成版本、覆盖区间、来源依赖。阅读账本是工具实际返回的机器记录，不能让摘要模型把“没读过”改成“已核验”。

```text
原始事件 / 资料固定版本 ──→ 私有工作库、片段索引和完整输出
                                    │ 按权限与问题选取
                                    ▼
活跃输入 = 有效指令 + 任务状态 + 带出处摘要 + 最近完整回合 + 必要片段
                                    │ 接近预算
                                    ▼
             大结果外存 → 缩减旧结果 → 滚动摘要 → 重新核算
```

所有截断点必须保持工具调用与结果按 ID 成对，包含并行多调用、失败结果及恢复后的记录。课程 s08 已有切点保护和“新结果先落盘”的逻辑；仍需针对当前 SDK/模型提供方的消息协议验证，不能直接复制 Anthropic `tool_use/tool_result` 对象。

上下文预算要包含系统提示、工具 schema、摘要、历史、检索片段和预留输出。课程 50,000 字符等常数是教学参数，不是当前 DeepSeek 的真实 token 上限。使用已核实的模型能力和可用计量做保守估计；无法精确计量时明确标注估算。摘要调用同样占时间、模型调用与 token 账本，不能抢走最终交付的预留资源，也不恢复已用掉的工具额度。

官方说明同样采用先清理旧工具输出、再按需总结，并明确早期细节可能丢失。因此有效约束需要独立持久化，不能只期待摘要完整保留。[Claude Code 上下文管理](https://code.claude.com/docs/en/how-claude-code-works#the-context-window)。

### 4.1 不能照搬的教学细节

- s08 的 `snip_compact` 按消息数归档中间段；`summary_input` 过长时只保留头尾。中间的纠错、限定条件可能因此不进入摘要。我们的裁剪必须先确保有效约束和新证据已覆盖，再按完整回合处理。
- s08 的“未见结果”依据最近 assistant 消息位置推断；跨请求失败、取消和恢复时，不能等价为模型成功收到结果。项目用请求/回合状态记录，且不把“已收到”夸大为“理解正确”。
- 同一固定版本中，s15 的 `summarize_history` 只取序列化历史前 80,000 字符，和 s08 的头尾选取不同；s15 的压缩返回消息也没有包含它已保存的 transcript 路径。不能认为“集成章节”自动保留独立章节的全部性质。
- 模型生成记忆不能自动成为研究事实；资料正文中的命令、旧摘要中的授权请求都保持数据身份。s09 的自动抽取、全文模型整理不直接接入当前研究证据仓储。

代码依据：[s08 ContextCompactor](https://github.com/shareAI-lab/learn-claude-code/blob/ce8f9f186058939da54c9d6fead78dfb5d0fd6c3/s08_context_compact/code.py#L254)、[s15 摘要实现](https://github.com/shareAI-lab/learn-claude-code/blob/ce8f9f186058939da54c9d6fead78dfb5d0fd6c3/s15_integrated_harness/code.py#L2176)。以上是实现边界分析，不是对全部课程的安全审计。

## 5. 独立沙箱与存储的决定保持不变

课程 s06 的隔离仅在消息层；s13 的队友在线程中运行，可选 worktree 解决文件修改冲突。它们都不满足每个专家独立 OS 沙箱。s03 也明确字符串拒绝列表不能作为完整安全边界。[s03 权限说明](https://github.com/shareAI-lab/learn-claude-code/blob/ce8f9f186058939da54c9d6fead78dfb5d0fd6c3/s03_permission/README.zh.md)。

Anthropic 官方的内置 Bash sandbox 使用 OS 机制，但该功能默认覆盖 shell 及其子进程，文件工具、MCP、hooks 在该边界外。我们的隔离要求覆盖整个专家本地执行和存储，不能仅给 Bash 加包装便声称达标。[官方沙箱边界](https://code.claude.com/docs/en/sandboxing)。

继续采用：每会话独占持久卷和 SQLite，运行时容器化；只挂自己的卷，初版无外网，模型和业务工具经过可信协调器的绑定通道。主助手模型遵循同样边界。邮箱、摘要、transcript、检索索引、模型输出都属于隔离和撤权的覆盖范围。任一依赖撤权时，按原决策淘汰旧工作区授权世代，不能将旧摘要偷偷复制到新卷。

课程把存储路径直接放在上下文中；我们跨沙箱传递的是校验身份的产物引用。专家内部可使用自身工作卷路径，但不能把另一专家的绝对路径当作授权凭证，更不挂载整个共享报告或 blob 目录。

## 6. 按可验收能力分层实施

沿用独立沙箱决策中的实施顺序。本补充只细化各阶段能力，不在本轮改生产实现。

| 层次 | 交付条件 |
| --- | --- |
| 单专家完整闭环 | 容器接任务、保存笔记与完整输出、凭引用重新读取、提交正式结果；重启后私有数据可用 |
| 多专家与主助手隔离 | 两专家相互不可读，主助手也不能任意读草稿；中央事件可靠交接，等待资料、撤权、取消端到端成立 |
| 上下文选择 | 所有入口先投影再检查输入；目录和正文可分页；读取日志区分返回片段和核验结论 |
| 确定性压缩 | 大结果落盘、旧结果缩减、完整回合保护；磁盘写失败时不丢原文 |
| 滚动摘要与恢复 | 增量游标、来源和约束保真、有界错误补救、调用级检查点、预留最终交付；通过真实任务质量回归 |

新增验收重点：

- 把关键纠错放在超长历史中段，压缩两次后仍能正确解释其适用范围并回查出处。
- 单个新工具结果就超过预算时，模型先得到可读预览和有效引用；不因摘要而丢失这个结果。
- 多个并行工具结果跨裁剪边界时，调用 ID 仍完整匹配；超限补救次数有上界。
- 摘要前后相同问题、相同权限能定位同一固定版本证据；来源撤权后笔记、摘要和全文缓存均不能进入新执行。
- 统计每请求输入、摘要成本、回查次数、无新增证据的重复读取、最终交付率和关键约束保留率；不凭“文字变短”宣布质量提高。
- 事件投递后协调器崩溃再启动，事件不丢、正式交付不重复；恢复不会清零预算。
- 检索使用标注样例核验正确片段是否入选，以及错版本、跨研究、无关重复片段是否被排除；不能用 top-k 参数代替质量验收。

本次只新增研究文档及来源索引，并更新两份原决策文档的交叉引用。未安装新框架、运行课程测试、调用付费模型、启动 Docker、修改生产代码或访问历史数据库。沙箱运行能力及压缩效果仍待实施后验证。
