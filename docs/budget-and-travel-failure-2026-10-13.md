请求已成功发送；8192 输出额度同时供推理与正文使用，正文可用额度分别只剩 4536、4267 tokens。两次都在第一个模型请求截断，尚无完整保存交付。供应商返回的两次总用量均为 11199 tokens；旧错误路径把它们记录为未确认，所以产品里的 0 tokens 不等于实际没有消耗。数据库并非本次失败根因。

[DeepSeek Responses 文档](https://api-docs.deepseek.com/guides/responses_api/)明确把 `response.incomplete` 定义为携带完整 response 对象的截断结束事件。该事件可以确认用量，但不能证明正文完整。

## 当前默认值

| 项目 | 默认值 | 接入位置 |
| --- | --- | --- |
| 最大费用 | 不限 | 普通运行无费用上限；移除协作的累计 token 硬限制 |
| 最大 Agent 回合 | 不限（JSON null） | RunLimits、SDK Runner、broker、账本、进度及摘要检查 |
| 原始上下文窗口 | 200000 tokens | RAW_WINDOW_TOKENS |
| 有效上下文窗口 | 180000 tokens | WINDOW_TOKENS，投影与发送前检查 |
| 工具裁剪阈值 | 60% | ModelProjection |
| 整体压缩阈值 | 70% | 裁剪后的 ModelProjection.context_pressure → Compactor |
| 最近工具正文 | 3 个 | 投影与运行轨迹摘要的保护边界 |
| 空闲微压缩 | 300 秒 | 私有工作区记录上次运行结束时间；下次继续会话首次投影执行 |
| 单次任务输出 | 16384 tokens | model_settings；摘要 8192，记忆查询 2048 |

这些是用户指定的本项目预算，不是供应商模型能力声明，也不切换当前模型名。有效窗口占用按完整输入估算加输出预留和安全余量计算。比例阈值包含预留，确保生成前留出空间；初轮采用 UTF-8 字节保守上界，续轮优先复用已确认供应商测量。估算与实测在账本中分别记录。

普通入口去掉固定 8/12/20 回合默认值。已明确批准的有限任务、研究计划、评测费用约束仍按其显式配置执行。任务时间、工具调用次数、并发及委派深度并未在这次请求中改为不限。

裁剪保留调用与结果配对，把较旧正文保存为可读取的固定工件；新结果只有在硬窗口确实不足时才缩成有正文、有前进游标的页面。整体摘要不吞掉最近 3 个工具结果，不改写用户原话，引用仍需匹配原始工件。空闲微压缩不调用模型，CLI 退出期间不需后台进程；恢复后首次发送前执行。

## 截断处理

`response.incomplete` 使用独立异常类型；`max_output_tokens` 保存为 `output_token_limit`，其他未完整状态保存为 `model_response_incomplete`。有供应商用量时确认并记录该用量，无用量时继续标记未知。截断正文不会作为成功结果发布，也不会因本修复自动重新收费调用。

源代码修改需在现有服务进程重启后生效；历史两个失败记录保持原样。本次没有声称 16384 能容纳任意长度任务，也没有把确定性测试当作旅行内容的实际交付验收。
