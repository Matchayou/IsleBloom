## 真实生成器协议检查

在不创建方法资产的前提下，使用相同 `CoreRunner`/`OpenAIEngine`/`CandidateDraft` 结构化输出契约对通用单位核验经验做了一次探索生成，见 [生成器运行](stage10-live-generator.json)。一次调用成功，返回且仅返回 `instructions` 与 `examples`；生成内容无案例公司名、来源 ID 或原文事实。已报告用量为 1 次请求、387 input tokens、2,584 output tokens。这份草稿是 **non-publishable**：通用经验来自开发观察，而非可归因的方法错误反馈；未进入 `AssetVersion`，没有 active 变化，不能用来声称质量提升。

首次尝试调用真实生成器时，自动审批阻止把仓库方法指令传给外部模型。随后本地核对 active `extract-v1` 与仓库通用基线逐字一致，长度 342 字、示例为空，未发现 URL、邮箱、密钥模式、公司或资料标识；携带这些核对证据重新提交后调用获准。没有改用绕行路径。

## 结论与继续条件

已验证：真实 DeepSeek 模型能运行当前单位提取方法，并可通过 Stage 10 生成器的结构化输出契约。未验证：新方法比 `extract-v1` 提高真实质量、降低真实费用或保持跨专家端到端收益；这次没有可正当地归因于方法的失败，因此不提出发布请求。若后续出现经核验、归因于方法的真实反馈，应在生成前冻结开发/留出集及质量、范围、成本门槛，再按 Stage 10 服务完成双臂重跑、下游检查、独立费用证据和用户最终确认。失败或费用未知均保留并阻断发布。
