# C4 真实模型自主补查验收

当前结论：**报告格式纠错与双侧交付后的汇总机制已实现并验证；C4 全部语义条件仍未通过。** 下文保留早期失败证据，最新机制复验见末节。真实复验使用真实模型与网页提供方。

## 案例与自主范围

隔离 8783 项目 `c4-autonomous-research-1`，主任务 `c4-autonomous-research-1-main`。

先上传一份专门编写的未核实简报：美国 2025 年第四季度零售电商占比，A 线索为 16.6%，B 线索为 18.3%，未给口径和计算表。此简报不是官方证据。第一阶段限定只读简报，由 `expert_search` 和 `expert_synthesize` 分别形成初步报告；两份报告都成功且为待复核状态。

第二阶段只给自然语言要求：允许联网，让两位专家各自补查官方原始资料，解释数字含义和差异，目标限定为 2026-03-10 首次发布的 2025Q4 数据。不提供搜索词、网页地址、工具参数或口径答案。主助手自行选择原会话、创建补查任务、编写调查要求；专家自行搜索和抓取。初步报告和失败记录均保留。

验收方另行读取官方 [Census 原始 PDF](https://www2.census.gov/retail/releases/historical/ecomm/25q4.pdf)作为核对依据，未把该正文或答案注入模型会话。文件确实分别列出季调占比 16.6% 和未季调占比 18.3%，因此核心待查问题有可取得的公开答案。

第二轮关键运行：

- A：`718126b5-32eb-4bf0-9c14-fe8d4475096d`，成功。完成资料读取、2 次搜索、2 次抓取；抓取来源为 Census 原始 PDF 和 FRED 序列页。
- B：`c796faaf-794d-4435-b53c-ed3f46a83324`，失败。已完成 4 次搜索、3 次抓取，来源包含 Census 原始 PDF、Census 栏目页和 FRED；失败码为 `model_behavior`，诊断为 `Invalid JSON when parsing model output`。此处是最终报告格式错误，不是工具参数 JSON 错误，也不是未找到资料。
- 主助手原回合：`b3c6120b-ba97-4955-9984-8ed32557ba7a`，180 秒超时。
- 主助手后台续接：`8ce54926-18d9-4e9a-afff-fd5edca2ca8a`，成功。保留 A 的待复核状态，说明 B 失败属于执行问题，没有把它当成来源不存在或某一数字错误的证据。

本轮没有自动正式采用结果，也没有把双专家一致意见冒充独立复核。A 对核心口径的解释与验收方读取的官方 PDF 一致，但其整份报告未经过正式独立复核；这不等于整份报告没有其他表述或计算问题。

## 验收中已修正的问题

普通专家原来的派发额度为 8 轮、8 次工具调用；持久执行为最多两次恢复尝试分配额度，导致单次实际只有 4 轮、4 次调用。市场专家此前独享较大的联网额度，全体专家获得联网工具后仍沿用这项区别，首轮因此在已取得正文后、交付前耗尽额度。

已移除按专家身份区分联网任务额度的分支：主助手派发的专家任务统一为 20 轮、24 次调用、360 秒；持久执行每次实际为 10 轮、12 次调用。主任务累计额度仍保留，金额上限仍按用户要求不设置。

工具执行核心现统一返回本次实际 `remaining_tool_calls`，覆盖普通专家及主助手，移除主助手单独按事件估算的提示逻辑。加入取得足够直接证据后停止扩展、不得重复抓取和额度耗尽时交付已有结论的规则。测试核对实际剩余次数、重复信息请求不再次咨询，以及累计任务额度。

定向回归：**61 passed / 8 skipped**。完整回归：**275 passed / 176 skipped**。跳过项不视为通过。

## 第二轮结束时尚未通过的条件（历史）

1. B 的最终报告输出格式错误尚不能像工具参数错误一样在同次对话中修正后交付。
2. 本次主助手采用串行等待，原始回合超时；已有后台续接保住了失败说明，但没有获得两侧成功报告后的完整判断。
3. 续接目前只转述已保存结果。本例缺少 B 的有效报告，主助手也没有在该续接回合对新来源进行进一步核对，不能把它记为完整证据比较通过。

下一次验收应保留初步报告，验证最终输出可修正交付，以及独立补查通过后台派发/续接完成汇总。不能单纯因搜索与抓取工具调用成功，就把 A15 或 C4 标为完成。

复现入口：`scripts/verify_collaboration_c4_autonomous_research.py`。既有 attempt 文件不覆盖；`--resume-from` 延续已有项目并保留其原任务及失败记录。该脚本的执行检查不替代本页语义审阅。


## 2026-10-04：格式纠错与后台汇总机制复验

实现见 [机制说明](collaboration-report-delivery.md)，完整证据见 [本轮记录](collaboration-c4-delivery-live-verification.json)。项目为 `c4-autonomous-research-3`；原来的项目、报告及失败记录均保留。

- 两位专家第一阶段均成功交付；主助手后台自动汇总成功。随后同一对专家在原会话分别自主搜索并抓取官方资料，未预先提供搜索词、官方 URL 或口径答案。
- A 补查运行 `feed5d43-3e32-4229-b1f5-bec9581b4f30` 的最终草稿出现真实 JSON 错误：第 2 行第 864 列缺少逗号或右大括号。草稿长 18,164 字符，原文与字段级诊断保存于 `output_repairs`。同次执行纠正一次后成功交付；9 次模型请求的用量全部记录。纠正回合没有工具，不重新执行搜索。
- B 补查运行 `a69bbbb7-c3b5-4a70-874a-203dab635c4a` 直接成功交付，无格式纠正。B 同时真实触发一次向主助手索要阶段一资料的交接，并收到答复后继续完成报告。
- 本次真实格式故障发生在 A。B 的格式故障分支由真实 SDK 配合受控模型覆盖；机制对所有专家适用，不能写成“本轮 B 现场纠错”。
- 主助手派发回合成功结束，没有等待专家而超时。专家都结束后自动续接，但首轮汇总准备因两份全文直接嵌入初始输入、超过 30,000 字符限制而被阻塞。已改为结果目录与短预览，正文通过工具按需读取。
- 第一轮操作员汇总重试触发读取工具失败，随后补齐批量正文过大时的可恢复反馈：选更少引用，或对已获准的大资料定位片段。权限撤回仍终止访问。第二轮汇总重试 `aebcb372-45e4-417f-b0c4-2fb13774cbbc` 成功，读取报告及共同原始来源，生成综合报告。
- 重试只运行主助手汇总。前后四份专家任务、运行、原报告和回执完全一致，未重新运行专家；两侧通知均确认完成，没有正式采用任何待复核报告。

**证据边界**：修复后的同轮等待、长报告按需读取、格式修正后汇总以及失败后部分汇总由受控集成测试完整覆盖。真实模型完成了格式纠正和双侧报告汇总，但中途修复后有操作员触发的汇总重试，不能描述为从头到尾无干预成功。

### 内容审阅

最终汇总正确识别官方首发文件、16.6% 对应 adjusted、18.3% 对应 not adjusted；列出分子分母、1.7 个百分点差值，并说明不能解释为时间增长。它保留 Table 2 标准误分歧，没有强迫双方一致，也没有把两名专家一致等同于独立复核。

仍有表述问题：概括为“全部来自季节调整”过窄，正文同时涉及交易日和移动假期调整；称阶段一报告原文“不可得”也不准确——原报告仍保存在任务中，主助手可通过 `read_context` 目录选择读取，只是该回合未读取。以上保留为 C4/A15 的语义验收缺口，不以技术执行成功抹去。

最新完整回归 **285 passed / 176 skipped**；长报告/大资料及协作定向回归 **34 passed / 6 skipped**。同轮两个专家共享两次汇总重试额度的专项测试通过。
