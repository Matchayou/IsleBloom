## 1. 本次解决的问题与开发边界

当前系统已有固定 TaskSpec、scope、资料/报告引用、任务依赖、信息交接、验收与采用状态，以及 DBOS 任务级恢复。主要缺口是：专家仍缺统一的受控执行入口；草稿纸和大结果没有统一的私有外存契约；长历史在模型调用前就可能触发字符限制；无法准确说明每次模型请求选了哪些信息；预算、压缩和调用级恢复尚未形成统一闭环。

目标产品行为：每个主助手/专家通过可信服务内的受控工具执行，把完整资料、笔记和运行记录保存在窗口之外；每次只取获准且与任务有关的内容；上下文不足时可继续检索，过长时可追溯地压缩；通过固定任务和正式产物协作。编码专家同时获得任务专属 worktree，改动、测试和交付绑定同一代码快照。

本计划采用独立编号 **CE1–CE8**，不覆盖旧 Stage、C1–C5 或 R 系列记录。已有协作阶段的未完成项仍以[协作开发进度](collaboration-development-progress.md)为准；旧测试结果只作历史依据，不算新架构通过。每个 CE 阶段执行[每阶段开发与验收流程](development-acceptance-process.md)，缺少真实外部验证时记“待验收”。

## 3. 数据与接口契约

以下是最小字段与职责，不要求每一行新建一张表。优先扩展现有值对象与仓库；仅在实际实现阶段创建需要的模块，不先搭插件框架。

| 契约 | 必须表达的信息 | 权威位置及约束 |
| --- | --- | --- |
| 执行绑定 | research/session/task/spec/run/attempt、授权世代、工作区身份、写者凭证 | 协调器绑定通道；不能信任模型正文中的自报身份 |
| 任务能力 | 固定输入/结果引用、允许工具、写入范围、完成条件、预算；编码另含仓库和基线 | 扩展现有 `TaskSpec`；能力与已有授权取交集，续聊修改形成新版本 |
| 私有工作记录 | 笔记、待核验判断、完整结果索引、来源依赖、内容哈希 | 会话 SQLite + 文件；笔记可编辑，不可改中央授权或核验状态 |
| 阅读账本 | 查询、固定版本、实际返回范围、响应引用/哈希、完整/摘录/无匹配状态 | 中央记录真实读操作；私有索引辅助整理，不伪称模型已经理解 |
| 请求上下文清单 | 请求 ID、候选及选入/排除引用、原因、原文/摘要/预览、范围/截断、保护项、覆盖游标、授权世代、输入哈希、预算估算 | 协调器保存经过校验的请求记录；区分已组装、已发送、发送结果未知，不把组装等同于已调用 |
| 摘要记录 | 输入消息区间、前序摘要、覆盖游标、约束/纠错引用、来源依赖、前后大小、状态、实际用量 | 正文存私有目录；只有验证成功才推进摘要指针，原始消息不覆盖 |
| 运行账本 | 模型/工具/摘要/修复尝试、已用与预留预算、未确认请求、当前阶段 | 中央持久化；请求前占用额度，响应后结算，恢复不清零 |
| 产物交付 | 完整产物引用/哈希、简报、完整性、截断标记、保存状态 | 正式产物走现有中央提交；简报和 UI 不各自形成不同“完整版本” |
| 安全检查点 | 固定任务/方法/模型、授权世代、输入依赖、私有快照引用、账本游标；编码含冻结快照 | DBOS/中央记录决定恢复资格，不能由可编辑 notebook 自行授权 |

原始请求正文、transcript 和清单按同等敏感级别管理，不写入公共日志。清单保存引用及必要元数据，正文按需受控回查；不能为了审计又把所有资料全文复制进中央日志。任务需要的原文缺失、授权失效或不可满足的必需上下文预算应返回明确错误，不丢掉必需项后继续。

`RunResult` 继续表达执行结果。沿用 `TaskReceipt` 的程序/语义检查、交付和采用字段区分运行结束、保存成功、验收通过、正式采用，不建立平行状态系统。`researching / finalizing` 是执行内阶段，不能与 `pending_review / rework / adopted` 混成一个状态枚举。

## 4. 分阶段实施

### CE1：一个专家的受控工具执行与逻辑数据隔离

**可使用结果：** 一个研究任务运行现有 SDK，调用获准模型与资料读取工具，保存并重读私有笔记，提交现有结构化成果；新进程重读笔记哈希一致。

实施内容：

- 可信应用运行完整 SDK 循环，经受控 broker 调用模型和工具；不提供 Shell、任意代码、任意路径或任意 HTTP 工具。
- 固定研究/会话/任务/版本/授权世代与工作区；每次操作前后校验权限、取消、版本及预算。模型不能自报身份或选择私有根目录。
- 有界操作信封保存序号、操作 ID 和内容哈希，拒绝重放、超限、未知操作；完整工具结果持久化后才能交给 SDK。
- 私有文件原子保存并建立 SQLite 索引；同一工作区单写者，过期写者不能结算。不按年龄抢占，不承诺调用级精确恢复。
- 模型/工具预算持久化预占，未确认请求保留；取消 SDK 执行并阻止迟到提交；正式成果仍走既有 TaskLedger/TaskReceipt。

**修改落点：** `composition.py`、`controlled/` 的 engine/runner/protocol/broker/ledger/workspace，以及现有 TaskService 停止回调；沿用公开 SDK Model 接口和中央提交路径。

**验收：** 真实模型完成源读取、笔记写入/重读和结构化提交；真实 PostgreSQL 验证预算、取消、重放与单写者；笔记跨进程哈希一致；取消停止 SDK 调用并拒绝发布；保存重试不重复生成。容器、网络/进程/文件系统硬隔离和硬资源配额全部移出范围。

### CE2：主助手与全部专家入口接入相同受控工具契约

**依赖 CE1。可使用结果：** 两位专家并行工作，主助手可分工、获知进度、读取获准正式成果并综合；彼此无法读取私有状态。

实施内容：

- 覆盖主助手正常对话、主助手续接/咨询、专家正式任务和普通讨论四类入口；所有模型入口通过可信协调服务的受控工具运行。
- 复用 `ContextPacket`、`TaskRevision`、`TaskDependency`、`AgentMessage` 和信息请求/报告授权。依赖验证覆盖循环、未知前置和固定产物版本；已失败前置阻止依赖它的任务，不阻塞无关分支。
- 区分消息已送达和已消费；等待资料由 DBOS/现有持久事件挂起与唤醒，不用模型轮询。重复投递重放回执，不重复执行副作用。
- 撤权先封锁 broker 和正式提交，停止运行并隔离旧私有目录；新授权世代从仍获准的原始输入重建，不能复制旧笔记/摘要。迟到调用和迟到提交拒绝，跨研究复用同类型专家仍使用不同私有库。

**修改落点：** `research/service.py`、`research/chat.py`、`app/research_execution.py`、`collaboration/service.py`、`collaboration/information.py`、`collaboration/models.py`、`tasks/models.py`、`durable.py` 及相应仓库。复用已有依赖关系，不另建任务图服务。

**验收：** 四入口逐一证明确实进入 runner；两个专家无法通过工具读取彼此私有记录；主助手无专家私有记录读取接口；授权报告能交接，未授权报告不能；事件重复/重启不丢状态；运行中撤权后缓存、衍生笔记与旧世代结果均不能再用。

### CE3：上下文投影、可回查外存与请求清单

**依赖 CE2。可使用结果：** 长聊天和大报告不会再因无差别全量拼接而失败；Agent 能从目录定位资料、分段读取，开发者能解释本轮为何选取这些片段。

实施内容：

- 在 `context/builder.py` 当前字符限额校验之前完成业务投影，再接 SDK 每次模型调用前的输入过滤。只加 SDK filter 无法修复运行前的长输入问题。
- 固定顺序为当前指令/有效约束、任务与进度、已存在的有效摘要、近期完整回合、授权目录和必要片段。本阶段不提前制造摘要；过长历史先外存、给定位入口并按需读取。
- 目录、报告正文和单条超大工具结果都支持固定版本游标分页。返回真实范围、完整性、剩余信息和续页游标；单条超过页预算仍可分段，不能返回空页并误报完整。
- 大结果先确认全文落盘，再输出带引用的预览；精确重复按版本和范围消除。阅读账本与每请求清单分开，清单反映最终模型输入及排除原因，发送前再次验权。
- 分开核算字符、估算 token 和提供方实测用量；输入预算包含系统指令、工具定义、输出预留与误差空间。若必需内容不能装入，明确暂停/失败，不静默删当前要求。

**修改落点：** `context/builder.py`、`context/mounts.py`、`context/execution.py`、`context/tool_guard.py`、`adapters/openai.py` 与读工具；按需新增 `context/projection.py`、阅读索引和清单持久化。保留固定源版本和 scope 校验，不向模型开放全库搜索。

**验收：** 超过旧字符阈值的历史在有可用预算时完成任务；中段关键约束仍在；多页读完的哈希/范围可与原文对应；目录超过单页、单条超大、部分页剩余不足都正确标记；不同版本不误去重；清单与实际发送输入一致；清单失败不会发送不可审计请求。

### CE4：有界调查、可靠收尾与完整交付

**依赖 CE3。可使用结果：** 专家不会把全部额度花在调查上；到达收尾条件后交付证据支持的报告，或明确记录尚未解决的问题和未交付原因。

实施内容：

- 在现有预算中预留收尾轮次和时间，执行阶段为 `researching → finalizing → delivered / incomplete`，取消/撤权优先。`finalizing` 关闭调查工具；既有有界格式修复也计入预算。
- 使用账本识别同版本、同参数、同结果且期间无新增信息的重复。先提示已有结果引用，持续无进展才收尾；分页、新证据后的复读、纠错复核和事件等待不误判。
- 完整成果保存与简报分开，简报携带完整引用/哈希、完整性、截断信息。验收复用 `TaskReceipt`；评审超时或异常保持 pending/failed，不能通过。研究允许“证据不足，暂未确定”。
- 界面区分处理中、已保存待审、需返工、已通过、已采用等现有业务状态，并可打开对应完整产物；失败通知不伪装为正式报告。

**修改落点：** `core.py`、`execution/ledger.py`、`tasks/service.py`、报告提交/验收服务、`collaboration/service.py` 及 `frontend/src/workspace/` 对应展示。必要时拆出小型预算/进展模块，不再加一个调度器。

**验收：** 调查额度临近耗尽仍有收尾机会；工具真实停用；重复循环有界结束而正常等待不失败；评审不可用不会假通过；简报、UI、全文引用一致；保存响应丢失只幂等重试保存，不重新调用模型生成报告。

### CE5：编码专家的 worktree 开发与集成闭环

**依赖 CE4。可使用结果：** 编码专家在专属工作区修改和测试代码，主助手得到可审查、可复现的候选改动；多个候选可以在独立集成环境验证。

实施内容：

- 当前任务/方法/路由的类型与工具白名单主要面向研究。同步扩展 `tasks/models.py`、`methods/models.py`、`routing/models.py` 和对应路由/验收，明确编码任务、读写/测试/受控 Git 能力及成果 schema；不能只挂载目录就宣称支持编码专家。
- 按项目仓库、任务、固定基线分配专属分支/worktree；正常重试复用同任务工作区。受控文件工具只操作该任务目录，不开放共享 Git 元数据或用户主 checkout。
- `status/diff/版本读取/checkpoint commit` 由授权 Git 作业提供，限定仓库和引用、串行更新共享 refs，隔离执行并禁用 hooks、外部 diff/textconv/filter 等扩展。专家不能通过参数注入任意宿主命令。
- 当前受控模式不开放任意仓库脚本执行；CE5 开始前明确可信构建/测试工具的授权和执行条件，不能直接运行模型生成的任意命令。
- 交付前停止写入并冻结代码，覆盖获准 tracked/untracked 文件，校验路径/链接，排除凭据与无关构建产物；记录基线、内容/提交哈希、测试环境/命令/结果。代码变更后旧测试不再作为该快照的通过证据。
- 独立集成 worktree 汇集候选，在获准的可信测试环境运行组合测试；冲突形成明确处理任务。归档前保存未提交成果并确认无写者；撤权同时隔离代码、日志和构建缓存。

**修改落点：** 现有任务/方法/路由/成果和工具服务；按需新增 `coding/` 工作区与受控 Git 实现。复用现有正式产物仓储保存代码交付元数据，不把代码 diff 伪装成研究证据。

**验收：** 两编码专家并发互不修改工作区；不能读共享 `.git`、其他任务分支或凭据；新增文件进入候选；危险路径/链接被拒；测试与快照一致；组合改动必须重新验证；取消/崩溃后未提交代码保留但不能越权发布。

### CE6：有来源、可诊断的增量压缩

**依赖 CE5。可使用结果：** 长任务跨越多轮后，主助手和专家仍能保留用户约束、已做决定、纠错与未完成事项，并能回查原文。

实施内容：

- 顺序固定为完整外存、确定性缩减旧结果、必要时滚动摘要。摘要输入是前次有效摘要加新增完整回合，使用明确覆盖游标，避免每轮重写全部历史。
- 最新指令和关键约束从权威记录保护注入，保留原句/消息 ID；摘要只携带事实状态、来源、纠错关系、已完成与待做事项，不充当系统指令或授权。
- 工具调用与结果成组处理，保留近期完整回合。摘要空白、schema 不合格、`finish_reason=length`、缺关键引用或无实质缩减均不替换历史。
- 摘要请求自身也做窗口和输出余量检查，计入中央预算。记录未调用/失败/成功、触发原因、输入输出大小和用量；失败不推进游标、不删除旧记录，不退回全量注入旁路。
- 提供方缓存 token 按实际口径归一化，不重复加到总输入；稳定前缀顺序可复用，不能为了缓存保留已撤权内容。明确窗口溢出最多重新投影补救一次，持续失败停止。

**修改落点：** CE3 投影/清单、SDK 过滤、私有摘要存储与执行账本；按需新增 `context/compaction.py`。只复用经过测试的 SDK 输入结构，不自行破坏工具调用协议。

**验收：** 中段重要信息、否定、纠错、固定版本和未解问题在压缩后仍可用；空/截断/无收益摘要被拒；失败保留原文和旧游标；撤权摘要不可复用；工具配对正确；摘要与格式修复不能形成预算外循环。

### CE7：安全边界检查点与细粒度恢复

**依赖 CE6。可使用结果：** 进程在已完成的模型/工具边界中断后，可从有效检查点恢复，避免重做已确认的读取与副作用；无法确认的外部调用如实呈现。

实施内容：

- 先验证当前 SDK 可导出/恢复的状态和暂停边界，再缩小 DBOS 现有整段专家重试的范围；不承诺任意 `await` 位置恢复，不增设另一套任务运行器。
- 检查点引用不可变私有运行快照，绑定任务、方法/模型、授权世代、来源依赖、代码基线/快照和账本。身份不符拒绝接续，工作区没有合法写者时才恢复。
- 工具副作用使用稳定操作 ID；结果已提交则重放回执。快照先可靠保存再发布中央引用；崩溃造成的孤立文件可回收，不能发布悬空检查点。
- 区分请求未发送、已发送未确认、响应已保存。外部模型发送后响应未落盘仍可能重试计费，记录未知用量和未确认尝试，不宣称 exactly-once；预占预算不能在重启后凭空释放。

**修改落点：** `durable.py`、`execution/ledger.py`、执行/结果仓库、SDK runner 与私有快照；按需新增检查点模块。代码快照与对话执行状态分开，DBOS 仍是唯一持久编排器。

**验收：** 真实进程杀死覆盖请求前、响应后保存前、事务写入未提交、提交后回执丢失；新进程检查实际记录；已提交副作用/产物不重复，预算不清零，未知调用保留；旧任务/旧权限/旧模型/错误代码快照恢复被拒。

### CE8：质量评测、回归与最终路径收敛

**依赖 CE7。可使用结果：** 有固定用例证明信息选取、压缩、协作与编码交付满足要求，并给出失败明细和实际成本，不以“token 更少”替代正确性。

实施内容：

- 固定任务、资料版本、模型/方法、限额与验收规则，比较基线、仅投影、投影加压缩。保存历史基线证据；不要为了比较在最终产品内保留旧执行后端。
- 用例包含中文/同义表达、长文中段事实、跨报告、用户纠错、跨年不可比指标、算术正确但业务解释不充分、旧追问与当前任务混淆、授权撤销、编码并行与集成冲突。
- 指标同时报告必需证据召回/版本正确性、重复读取、关键约束保留、语义质量、交付率、输入量、模型/工具调用、延迟、已知/未知用量。先登记判定标准；隔离越权、虚假通过、固定版本错用等用例零容忍。
- 现有词法检索确有实测缺口才单独提检索组件变更，不把向量库列为本阶段必做。真实模型语义评测与脚本/假模型契约测试分别出结果，保留失败样本。
- 各入口新路径完成必要回归后移除不受治理的旧执行路径、全历史拼接和旁路；历史只读归档保留，不迁移旧运行到新协议，不删除用户历史数据。

**验收：** 需求矩阵每项有实现和证据，四入口均覆盖；真实受控工具/数据库/进程故障验证齐备；全部阻断缺口关闭。未跑的外部用例、未解决的语义问题明确列出，不能借历史通过数宣布新架构完成。

## 6. 开发顺序与当前清单

执行顺序为 **CE1 → CE2 → CE3 → CE4 → CE5 → CE6 → CE7 → CE8**。对应统一选型的六阶段：CE1/CE2 分别对应隔离阶段，CE3–CE4 对应上下文与交付，CE5 对应编码，CE6–CE7 对应摘要与恢复，CE8 对应质量验证。

开发期间在独立环境逐段打通；某入口的新路径通过验收后，在该版本中删除对应旧路径，再做受影响回归。最终收敛检查遗漏旁路。运行时缺失、外部测试未完成时保持“待验收”，完成可执行工作并记录阻塞，本机可信受控执行是正式方案；不得用假数据库或假模型替代真实外部验收。无需为未来阶段预先建立空表、可切换后端或通用插件层。
