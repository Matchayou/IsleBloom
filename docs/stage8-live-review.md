2026-10-03。结论：**固定案例的版本绑定、来源隔离和恢复后的业务一致性通过**。核对者为 Codex，独立阅读实际输出与固定摘录；不是生成模型的自检，也不是用户/真人签收。不据此宣称模型稳定性、方法质量提升或 RouteLLM 双模型收益。工程全量回归为 336 passed。

## 实际执行与边界

- DeepSeek `deepseek-flash`，`https://api.deepseek.com`，现有 SDK Responses API。模板 `three-company-research/v8`，固定 `synthesize-evidence-v7` 和 `analyze-evidence-v7`。
- 两条路径的目标、方法正文/示例、来源版本及单次运行限额一致：180 秒、8 轮、8 次工具调用；原计划各 4 步、并发 3、总时限 600 秒。
- 模板四步首次发布成功。手工路径 GM 首次发生 SDK 输出契约错误；同输入重试成功。随后重新计算比较时一次引用匹配失败，固定输入再试成功。最终八个节点均有成功版本，两个比较均只挂载自己当前的三个上游结果。
- 本次记录共 **11 次运行**：初始 8 次及 3 次显式恢复调用，其中 2 次失败；首次手工比较的部分结果也保留。恢复使用既有 retry/adopt 命令，没有新增生产重试器或绕过计划幂等语义。两条路径累计调用次数不同，不能用本例证明同预算成功率或费用优势。
- 程序核对见 [stage8-live-checks.json](stage8-live-checks.json)，全部原始运行、输入与最终输出见 [stage8-live.json](stage8-live.json)，便读报告见 [stage8-live-reports.md](stage8-live-reports.md)。首次尝试的状态单独保留在 [attempt 10](stage8-live-attempt-10.json)，第一次比较恢复失败另存 [recovery failure](stage8-live-recovery-first-failure.json)。

## 输入、失败与用量

第 1–9 次尝试均保留，不挑选成功结果拼成一次全成功。它们暴露了接口误选、引用字段改写、跨行/制表符错误、冗余读取、单步时限缺口与 SDK 输出契约失败。第 6 次虽八步发布，独立复核仍发现引用不完整，未作为最后的语义结论。

第 10 次使用逐行空白规范化的公开年报摘录。原始文件不变；复用现有证据 canonicalization 断言规范化前后文字、词序及行数完全一致。原始/新 hash 和说明见 [输入清单](stage8-live-input-manifest.json)，新资料在 `stage8-packets/`。没有添加答案或删去难点，也没有修改生产解析器/证据校验器；本例不证明任意原始排版都能被模型可靠引用。

本次 11 次运行已报告 **47,530 input / 121,624 output tokens**，其中 **1 次失败用量未知**，所以这只是已报告部分，不能当作总计或把失败当作免费。历次尝试计数见 [尝试汇总](stage8-live-attempts-summary.json)。提供方响应诊断只保存消息正文、状态和用量，不保存请求头、密钥或思维链。
