# 每阶段开发与验收流程

本流程记录用户明确要求，后续阶段继续复用。只有设计符合性与必要测试均通过，才能宣布该阶段完成；依赖缺失的真实验证必须标为待验收，不能用脚本替身替代。

1. **冻结当前边界**：阅读最新阶段设计、源码索引和适用 AGENTS.md，列出当前阶段要求、前序已完成阶段、禁止提前实现的能力。保护现有文件与用户改动。
2. **先调查复用**：优先检查参考项目内部可靠适用代码、已有依赖的文档、类型和实现，采用成熟模式；优先公开 API，记录采用版本、来源、职责边界及不采用部分。源码摘选不视为可运行依赖；补齐完整依赖并锁版本。
3. **最小端到端实现**：先跑通当前阶段的输入到可观察结果，再逐层补齐当前要求。职责分离，不建未来模块空壳，不加兼容层、自动 fallback 或迁移路径。
4. **逐项设计核对**：为每项要求记录设计来源、实现文件/接口、测试或交互证据、剩余 gap。不能只以测试数量代替符合性判断。
5. **最小 gap 修复循环**：定位到实际边界，明确补齐所需最小内容，修改后重跑受影响测试，再核对设计。失败记录和修复证据保留在阶段报告。
6. **连通与回归**：当前阶段设计符合后，执行本阶段完整链路与所有前序已完成阶段的必要回归；记录命令、退出码、结果。Stage 0 没有前序 Stage，建立 C0 基线。
7. **真实语义/外部验收**：用少量固定真实交互检查模型行为或外部系统；记录配置标识（不含密钥）、实际结果与限制。脚本引擎验证控制契约，假模型驱动真实 SDK 验证映射与循环，两者均不等于真实模型语义通过。
8. **阶段交付门槛**：交付可运行入口、依赖与启动说明、符合性矩阵、gap 修复记录、实际测试结果、真实交互证据或明确未解决项。外部条件缺失时先完成全部可执行工作，报告“等待验收”，不宣称阶段完成、不自动推进下一阶段。

## Stage 1 留下的可复用执行细则

- 先复用依赖的事务公开 API，确认参考组件是否自行提交；跨模块原子性必须由应用通过公共仓库接口显式协调，不能靠多次成功调用推断。
- 执行成功、保存已确认、保存结果不确定分别建模。查询和幂等重试沿用原 ID/内容；重试保存不增加模型调用。界面回调失败单独隔离。
- 同一契约必须实际在内存与目标数据库运行；缺 TEST_DATABASE_URL 时明确 skipped，不能用于宣布持久化通过。
- 故障注入至少覆盖事务已写入但未 COMMIT、COMMIT 后响应丢失、重复投递、真实进程被杀。用新进程查询实际记录，检查结果、状态、消息数量和模型调用数量。
- 存活判断的依据要可验证：数据库连接消失不代表应用退出，不能仅依据年龄或旧连接判断。记录当前部署范围，范围外明确拒绝接管。
- 留存固定版本、命令、退出码、测试原始输出、独立 CLI 交互和未运行的真实评测原因。待外部条件齐备后只补缺项及受影响回归，不能拿历史真实结果代替本阶段验证。
